# 组合总览聚合范围钉扎(裁决稿)

*2026-07-14 · 状态:**裁决稿,domain-reviewer 评审中** · 前置:explorer-redesign §4/§6
(F2 最小披露已落地:场景列 + 口径脚注)· 实现分派:Opus(锚点先行)*

## 1 · 问题

分析案例覆盖导出/运行当时的**单棵事件树**;组合总览据此比较的是"各项目最近钉扎
场景",非项目全部风险。多 IE 项目被系统性低估,两个项目的条形可能在比
"全场景 vs 单场景"。现状靠披露(脚注+场景列)防误读,不解决口径本身。

## 2 · 裁决:新增「勾选集聚合」导出模式

- **触发**:报告导出与不确定性运行新增可选 `scope="checked_set"`(默认仍
  `single`,零扰动)。聚合 = 当前勾选的全部 ETA 页签。
- **数学口径**:聚合后果频率 = 各树同级后果频率**逐级求和**。
  论证:后果级 c 的年到达次数 N_c = Σ_树 N_c,t;**期望线性无需独立性**
  (E[ΣN] = ΣE[N] 恒成立)——各树共享底事件/屏障/参数只影响方差,不影响均值。
  因此逐级求和是**精确**口径,非近似。(不确定性分位带则相关:聚合 MC 须
  同一抽样下逐树求值再相加——settings 记 samples/seed,实现按此。)
- **钉扎形状**:一次 auto-pin 产生一个案例:`kind="report"|"uncertainty"`,
  `settings.scope="checked_set"`,`settings.scenarios=[{key,name},...]`(逐树),
  `results.consequences` 为聚合值;另存 `results.per_tree=[{key,name,consequences}]`
  逐树分解(页脚与追溯用)。**不改 DB schema**(settings_json/results_json 自由形)。
- **组合总览消费**:`store.portfolio()` 最新案例选取不变(仍取最新 report/uncertainty);
  前端案例来源列:`scope=checked_set` 显示「聚合 n 树」徽章替代场景名;
  旧案例(无 scope 字段)语义 = single,显示不变——**向后兼容零迁移**。
- **报告页脚**:聚合案例的证据行追加逐树分解表(名 + C1–C5 行)。

## 3 · 锚点(实现前先落)

双树手算:树 1(f=1e-3,单屏障 0.1)→ C1=9e-4, C2=1e-4;树 2(f=2e-3,单屏障 0.2)
→ C1=1.6e-3, C2=4e-4;聚合 C1=2.5e-3、C2=5e-4,Σ=3e-3=Σf ✓(守恒跨树保持)。
共享屏障变体:两树同一 PFD 参数——聚合均值不变(期望线性锁测,与独立情形同值)。
