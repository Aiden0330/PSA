# 调研:多系统对比 + 站级评估——既有软件怎么做(2026-07-25)

*触发:用户提出两个新功能 ①对比不同供应商 ESS 系统 ②评估整站(含系统间屏障)。
本文回答"现有软件支持吗、怎么做的",并为 4 个 mockup 方向提供依据。*

## 1 · 功能 ①(供应商系统对比)——业界怎么做

| 工具/实践 | 机制 | 可借鉴点 |
|---|---|---|
| RiskSpectrum PSA | **Analysis Cases + MCS Editor 比较**:同一逻辑模型挂不同参数集/边界条件,逐案例量化后在 MCS 编辑器里对比割集与顶值;敏感性分析内建 | "同结构、换参数集"是对比的正统姿势——我们已有 analysis_cases、模型 diff(parity #5)、B 级厂商数据层,拼起来就是它 |
| SAPHIRE (NRC) | 版本/工作区间割集对比(无独立"对比"大特性,靠导出比对) | 对比不必是新引擎能力,是**呈现层**功能 |
| 电池分析 SaaS(TWAICE/ACCURE) | 机队 KPI 记分卡横向对比(数据驱动,非 PSA) | 管理层视角的记分卡/矩阵 UX 参考 |
| 过程工业 QRA 咨询 | "设计替代方案对比"章节:同场景不同设计跑两遍,表格并排 + Δ 归因 | 报告口径:**Δ 必须归因到具体屏障/参数**,否则监管答辩无力 |

**结论**:没有商业工具把"供应商对比"做成一等公民;都是"同模型结构 × 多参数集 × 结果并排"。
我们的既有件(分析案例、canonical 模型 diff、组合总览 API、参考库 B 级厂商层、重要度)已覆盖
后端所需 ~80%,缺的是**对比工作台 UI**与"Δ 归因"呈现。

## 2 · 功能 ②(站级评估 + 系统间屏障)——业界怎么做

| 工具/实践 | 机制 | 可借鉴点 |
|---|---|---|
| **RiskSpectrum Multi-Unit PSA**(riskspectrum.com/multi-unit,已核验) | **复用单机组 MCS 列表**拼站级,不重建大模型;另行申报**跨机组清单**:多机组共因初因、共享设备、跨机组 CCF、跨机组人因依赖;输出站级释放概率,实测"计入跨机组依赖后多机组释放概率上升" | 直接同构:舱=机组。站级 = 单舱模型输出(频率/MCS)× 站拓扑 × 跨舱依赖清单(同厂 BMS 固件 CCF、共享消防水源、同一运维班组人因) |
| 过程工业**多米诺效应分析**(文献成熟,无主导商业软件;Safeti/RISKCURVES 只做后果场) | 升级向量(热辐射/爆炸波/碎片)→ probit 升级概率 → 事件树/贝叶斯网络逐级扩展;Aripar-GIS 等学术工具做站域风险合成 | 舱间蔓延 = 多米诺:**一级事件(舱 i 火灾)× 升级概率(间距/防火墙 PFD)× 二级受体** —— 我们的 ETA 天生能表达,不需要 CFD |
| DNV BESS 站级 QRA(publications 154811,咨询交付) | 场址 QRA:逐舱场景 + 间距/朝向 + 后果叠加,人工建模 | 报告结构参考;证明"站级"是真实监管需求而无软件化产品 |
| UL 9540A Ed.6 installation-level + NFPA 855 | 确定论:隔距/防爆墙合规测试,不含概率 | 我们的站级屏障(B_SPACING/防火墙/泄爆)PFD 化后,与规范条款互引即证据链卖点 |

**结论**:核电 MU-PSA 给了**方法骨架**(复用单元结果 + 跨单元依赖清单),多米诺文献给了
**蔓延数学**(升级概率×受体),但**没有任何 BESS 商业软件把二者装进一个产品**——这正是本
工具"下一代"定位的空档。

## 3 · 映射到本工具(已有 vs 缺口)

已有:多项目槽 + 组合总览聚合(`/api/portfolio`)· 分析案例 · canonical 模型 diff ·
产品维度(cell→IE 换算,舱级频率现成)· B_SPACING/B_DEFLAG/应急响应等站级屏障条目 ·
CCF β/alpha 引擎 + SOKC · 不确定性三通道。
缺口:①对比工作台 UI(Δ 归因视图);②站拓扑数据结构(舱实例×供应商模型引用×舱间屏障边)
+ 站级序列量化(可先按 MU-PSA 式"单舱结果 × 蔓延树"落地,不动引擎);③跨舱 CCF 申报面板。

## 4 · 四个 mockup 方向(docs/design/mockups/2026-07-25-*)

| 方向 | 文件 | 一句话赌注 |
|---|---|---|
| A 对标矩阵 | `compare-matrix` | 分析师信表格:RiskSpectrum 式密度,逐序列/逐屏障 Δ,归因即证据 |
| B 决策仪表盘 | `compare-dashboard` | 管理层要一眼定论:矩阵叠加 + Δ 瀑布归因 + 不确定带并排 |
| C 站级拓扑画布 | `station-topology` | 拓扑即模型:平面图上摆舱、连屏障边,点舱看系统级,蔓延圈层直读 |
| D 站级序列(MU-PSA 式) | `station-eventtree` | 复用既有 ETA 机制最快落地:站级事件树 + 跨舱 CCF 面板 |

推荐:功能①取 **A 为主、B 的 Δ 瀑布并入**;功能②取 **D 为骨架(先能算)、C 作导航壳
(后加)**——D 直接复用现引擎与证据链,C 是第二阶段的呈现层。

## 5 · 第二轮方向(2026-07-26,应用户"more options"追加,功能①专属)

| 方向 | 文件 | 一句话赌注 |
|---|---|---|
| E 单树双值 | `compare-tree-mirror` | PSA 工程师用树思考:同一棵事件树、每分支双色双值,分歧发生在哪一跳直接可见;◇ 结构差异由版面禁止硬比 |
| F 屏障墙 | `compare-barrier-wall` | 业主/监管按纵深防御层思考:同类屏障纵向对齐、墙厚=拦截率,"最薄一堵墙"红框对齐即结论 |
| G 报告文档式 | `compare-report-doc` | 交付物就是文档:对比页=报告第 5 章形态,数字带溯源角标,签核栏/免责/案例组指纹原生 |
| H 多准则记分卡 | `compare-scorecard` | 选型委员会按多准则打分:权重可调且显式披露,雷达讲均衡;低置信画像虚线弱化,分数不进证据链 |

八方向合并推荐(A/B/E/F/G/H 均为功能①候选):**E 作对比页主视图**(与 ETA 画布同语言,
分析师零学习成本)+ **A 的序列/割集密度表作下钻层** + **G 作导出形态**(对比页一键成章)。
B 的瀑布并入 E 的侧栏;F 适合放进报告作"纵深防御图";H 仅当用户确有多准则委员会流程再做。

## 7 · 站级页第二轮方向(2026-07-27,应用户"new options"追加,功能②专属)

| 方向 | 文件 | 一句话赌注 |
|---|---|---|
| I 蔓延矩阵 | `2026-07-27-station-matrix` | 矩阵在 40+ 舱仍可读(地图会糊);行/列求和即"最危险源/最暴露受体"排名,格 = 可编辑的屏障边——它是 D 方向站级树的**边编辑器**,不是另一套模型 |
| J 纵深漏斗 | `2026-07-27-station-funnel` | 整站的故事 = 一条链上的 5 个数(1舱→≥2舱→≥5舱→全站,闸=屏障组);站界外**不嵌套**单列防误读;跨舱 CCF 开关示低估幅度 |
| K 配置工作台 | `2026-07-27-station-config-studio` | 站级页的真实任务是设计决策:舱数/配比/间距/墙密度/消防的 what-if,站型=可钉扎版本,与功能①同一对比机制;成本列仅并排呈现用户填报值 |
| L 验收仪表盘 | `2026-07-27-station-acceptance` | 审批人要 pass/fail + 签字:概率准则(p50 过 + p95 超 ⇒ 有条件通过,判定规则本身禁均值叙事)‖ 规范符合性并列不折算;逐舱小倍数抓异常舱;签发走既有评审状态机 |

六方向合并推荐(C/D/I/J/K/L):**D 仍是骨架**(先能算);**J 作站级页首屏**(漏斗即结论,
每个数下钻到 D 的序列表);**I 作边编辑器**(舱数 >20 时替代 C 的平面图;C 降级为二期
导航壳);**L 是签发出口**(复用评审状态机);**K 二期**(依赖站型版本化 + 功能①对比机制,
是两个功能的合流点)。
