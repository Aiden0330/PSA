# 储能热失控事件序列与防护屏障框架（bess-tr-event-tree）

为储能（BESS）锂离子电池热失控构建**可量化的事件树**:把"触发 → 电芯演化 → 蔓延 → 后果"这条物理链转成事件树的分支节点,把纵深防御屏障映射到每一步转换,并给出后果分级（C1–C5）、前兆信号与探测窗口、以及可直接对接量化引擎的模型脚手架。

本技能是**领域内容层**:产出的事件树模型交给引擎 `psaengine/`(技能 `psa-engine`)做精确定量,在前端(技能 `psa-frontend`)渲染编辑。面向 BESS 热失控 QRA,但框架对其他锂电场景通用。

> **当前实现(2026-07)**:本框架已落地——链条/屏障/后果数据在 `bess/tr_model_data.json`(驱动 `bess/tr_model.py`),5 个内置初始事件场景树在 `bess/scenarios.json`(内短/过充/液冷/外火/机械进水,`GET /api/bess/scenarios`),C1–C5 在 `bess/consequences.py`。**修改事件树结构或屏障时改这些数据文件,不要新写脚手架**;新增场景先读本技能 references 再落 `scenarios.json`。原蓝图 assets(`tr_event_tree.py`/`tr_model.json`)已被真实实现取代,归档于 `docs/skill-blueprints/`;前身工具的模板文件 `docs/reference-assets/templates-eta-claude.ts` 待迁移为模板库。

## 一、核心框架:链条即事件树（先读)

热失控不是单点事件,而是一条**逐级升级、每步可被屏障打断**的链。这是全部建模的骨架:

```
[触发层] 电气/热/机械滥用 + 潜在制造缺陷
   │  前兆:电压跌落、温升、绝缘下降
   ▼  屏障①:BMS 切断/接触器跳闸  —  电芯级 CID/PTC/陶瓷隔膜
[电芯演化] 自产热(50–60℃)→ SEI分解(80–120℃,起点)→ 开阀 → 离气/冒烟
           → 鼓包 → 隔膜熔毁(130–165℃)→ 全面热失控 → 起火(>250℃释氧)
   │  前兆:VOC/CO/H₂、压力、温升速率、烟
   ▼  屏障②:离气探测(2–30min 窗口)→ 烟探(VESDA)→ 热/火焰探测
[蔓延层] 电芯→模组(软包 60–80s)→ 电池簇 → 舱/系统 → 邻舱
   │  SOC>75–95% 决定能否自持;LFP 蔓延速度≈NMC 的 1/5
   ▼  屏障③:电芯间热障/间距  —  单元间距(≥3ft/914mm)
[后果层] C1 单体排气 → C2 模组蔓延 → C3 单舱火 → C4 多舱火
         → C5 爆燃/爆炸(舱内可燃气云)+ 毒气(HF 20–200 mg/Wh)
         ▲  屏障④:泄爆 NFPA68 / 防爆 NFPA69 / CCR / 应急响应(避免开门引气)
```

**关键认知:决定后果严重度的往往不是"是否发生电芯内短",而是"电芯间有无热障 + 舱内可燃气有无泄爆/防爆 + 探测与应急是否及时"。** EPRI 失效数据库显示多数事故根因在系统集成与平衡系统(BOS)/控制,而非电芯本身(集成/施工≈36%、运行≈29%、设计≈21%、制造仅≈4%;72% 发生于头两年)。建模时不要把全部概率压在电芯触发上。

## 二、如何把链条建成事件树

**1) 选定初始事件(IE)。** 从五类代表性 IE 起(详见 `references/initiating-events.md`):①电芯内短(潜在缺陷/锂枝晶)②液冷泄漏→电弧/外短→热滥用 ③过充/BMS失效(SOC>95%高危)④外部火/邻舱热辐射 ⑤机械损伤/进水。每个 IE 起一棵事件树或一条始发分支,频率用 EPRI 数据库与生命周期相位校准。

**2) 按演化阶段铺设屏障功能事件(表头)。** 事件树的功能事件(表头)就是屏障,按链条顺序排列。**6 个标准分支节点**(详见 `references/safety-barriers.md`):
`早期离气探测+联动? → BMS切断/隔离? → 电芯间热障阻断蔓延? → 舱内泄爆/防爆动作? → 舱间距阻断多舱? → 应急响应(避免开门引气)?`
每个节点二叉:成功(上)=屏障有效,失败(下)=升级。

**3) 把序列分箱到 C1–C5。** 末态按升级阶梯归类(详见 `references/consequences-and-incidents.md`):屏障越早失败、后果越高。典型:离气探测+BMS 成功→C1;热障成功→C2;泄爆成功但已起火→C3/C4;全失败→C5。

**4) 给每个屏障赋 PFD(失效概率)+ 出处。** 用 `assets/tr_model.json` 内的先验值(取自 Moa & Go 2023 / LOPA / DNV:BMS 0.1、冷却 0.1、热障 0.1、火/烟探测 0.01、灭火 0.1 且有效性 η=0.953、气体探测 0.01、应急通风 0.1)。**这些是待替换的先验,不是真值**;有现场/测试数据就贝叶斯更新。主动灭火等"启动但可能无效"的屏障用三结果分支(启动且有效/未启动/启动无效)。

**5) 交量化引擎。** 用 `assets/tr_event_tree.py` 生成结构,导出给 `fta-eta-quantification-engine` 做序列频率定量(始发频率 × 各分支概率连乘),或直接调用其内置枚举。屏障失败分支若由子部件构成(如"BMS切断"=传感∧逻辑∧接触器),挂一棵故障树(小ET/大FT)。

**6) 分场景定制三套模板。** 电网集装箱(泄爆/间距主导,户外被动)、户用(室内 UL 9540A 强制、壳体泄压)、数据中心 UPS(多为 NMC + VESDA + 离气 Li-ion Tamer + 洁净剂)。场景改变屏障集合与 PFD,见各 reference 的场景小节。

## 三、必记的领域锚点(深度见 references)

- **温度门槛**:电解液降解 50–60℃;SEI 分解 80–120℃(热失控起点);隔膜熔毁 130–165℃;>250℃ 正极释氧引发剧烈第二放热峰 → 起火。
- **探测窗口**:离气(VOC/电解液蒸气)最早,起火前 **2–30 分钟**预警 → 烟(VESDA)→ 热/火焰最晚。**离气探测是第一道可建模屏障,务必设为事件树首分支。**
- **蔓延阈值**:SOC>75–95% 才能自持蔓延(75% 常不足);软包 60–80s 贯穿模组;**NMC811 蔓延速度≈LFP 的 5 倍,峰温约 899℃ vs LFP 约 524℃**(Schöberl 2024)。
- **离气与毒气**:七种主组分 CO₂/CO/H₂/C₂H₄/CH₄/C₂H₆/C₃H₆,单体产气 1–3 L/Ah;**HF 20–200 mg/Wh**(Larsson 2017),POF₃ 15–22 mg/Wh。**"LFP 不产 HF"是被同行评议数据证伪的过度简化——LFP 单位电量 HF 产出可能更高。**
- **化学体系即风险分级**:NMC(尤其室内/数据中心 UPS)→ 更短窗口、更快蔓延、更高峰温、更剧烈后果(Moss Landing 2025 范式);LFP → 约 5 倍更长窗口但仍须建模 HF 毒气。

## 四、硬性规则与陷阱

- **爆燃必须独立建模。** 在 C3/C4 火灾节点后并联"舱内可燃气云爆燃"分支(NFPA 69 优先于 68,2026 版不再允许单独泄爆作主策略)。McMicken 表明消防员开门引气可在 2–3 分钟内引爆 → 把"应急响应程序"设为显式**人因屏障节点**。
- **厂商"无蔓延/零事故"宣称不可直接作屏障可靠性输入。** Tesla">6 GWh 无传播"、CATL"PPB 失效率"、华为"延缓起火 7 小时"、BYD"15 年零事故"等多为营销或单次测试,须以第三方 UL 9540A / 大规模火测(LSFT)报告核验。
- **屏障 PFD 与触发频率绝对值是最大不确定性来源。** 公开文献稀缺;用 `tr_model.json` 先验起步,务必做敏感性分析,并以 UL 9540A/LSFT(条件概率)+ EPRI 数据库(频率/相位)持续校准。
- **不要把概率全压在电芯触发上**(见框架认知);BOS/控制/集成才是主要失效环节。
- **根因本身具不确定性。** McMicken(内短 vs 外部电弧)、韩国 ESS、Moss Landing 均有未决根因 → IE 归类应在敏感性分析中覆盖多种假设。
- **阈值随设计变更失效。** 电芯化学/容量改变(280→314/320Ah)或采用无模组 CTP/CTS 时,离气特征与蔓延速度变化,须重测并更新探测阈值与分支概率。
